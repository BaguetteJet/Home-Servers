# ZFS
ZFS is a filesystem and volume manager that stores data directly on raw disks. It manages redundancy, pooling, and space allocation all in one integrated system rather than as separate layers.

This is an alternative approach to using a traditional RAID setup using `mdadm`. 

I use ZFS because it detects and repairs silent data corruption, and includes built-in compression, which saves disk space.


## Setup

### ZFS Install

Install ZFS
```bash
sudo apt update
sudo apt install zfsutils-linux
```

Confirm installation
```bash
zfs version
```

Run `zpool status` periodically to check drive states

### ZED Config
ZED (ZFS Event Daemon) listens for events generated by ZFS. This allows proactive failure notifications.

## Creating Mirror (2x 1TB)
Example creates `emc` pool from two drives

Using the drives `/dev/sdf`, `/dev/sdg`

Wipe old drives
```bash
sudo wipefs -a /dev/sdf
sudo wipefs -a /dev/sdg
sudo sgdisk --zap-all /dev/sdf
sudo sgdisk --zap-all /dev/sdg
```

Create the mirrored pool (I named mine `emc`)
```bash
sudo zpool create -m /mnt/emc emc mirror \
  /dev/disk/by-id/scsi-SATA_HUS722T1TALA600_WCC6M4XLVSRJ \
  /dev/disk/by-id/scsi-SATA_HUS722T1TALA600_WCC6M6KF041S
```
Replace disk IDs    
`-m /mnt/NAME NAME` makes pool look like a regular mount

Verify pool
```bash
zpool status emc
```

Check health
```bash
zpool list
```

*sample output:*
```
NAME   SIZE  ALLOC   FREE  CKPOINT  EXPANDSZ   FRAG    CAP  DEDUP    HEALTH  ALTROOT
emc    928G   158K   928G        -         -     0%     0%  1.00x    ONLINE  -
```

Set defaults
```bash
sudo zfs set compression=lz4 emc
sudo zfs set atime=off emc
sudo zfs set xattr=sa emc
```
`compression=lz4` compression is nearly free CPU-wise and often saves real space on backup data   
`atime=off` stops ZFS from updating "last accessed" timestamps on every read. Disks do less work, pools stay faster, and hardware lasts longer   
`xattr=sa` stores file metadata attributes more efficiently inside ZFS for better performance


## Using ZFS

Example creates `documents` dataset in the `emc` pool

Create dataset
```bash
sudo zfs create emc/documents
```

Ensure user permissions
```bash
sudo chown <user>:<user> /mnt/emc/documents
ls -ld /mnt/emc/documents
```

Check settings
```bash
zfs get compression,atime,xattr emc/documents
```
Update if needed

Enable auto snapshots
```bash
sudo zfs set com.sun:auto-snapshot=true emc/documents
```

Share through samba

## Snapshots

Install auto snapshots
```bash
sudo apt update
sudo apt install zfs-auto-snapshot
```

Check snapshot frequency
```bash
grep keep /etc/cron*/*zfs-auto-snapshot
```

Adjust how many snapshots to keep

Example: change kept `daily` snapshots from `31` to `7`
```bash
sudo sed -i 's/--label=daily --keep=31/--label=daily --keep=7/' /etc/cron.daily/zfs-auto-snapshot
```

Check snapshots
```bash
zfs list -t snapshot
```
*sample output*
```
AME                                                   USED  AVAIL  REFER  MOUNTPOINT
emc@zfs-auto-snap_frequent-2026-07-21-2245               0B      -    24K  -
emc/documents@zfs-auto-snap_frequent-2026-07-21-2245     0B      -    24K  -
```
**NOTE** pool is listed as snapshot, but excludes datasets. Dataset snapshots need to be enabled per dataset.

Enable auto snapshots on your chosen dataset(s)
```bash
sudo zfs set com.sun:auto-snapshot=true emc/documents
```

Rollback dataset
```bash
zfs rollback emc/documents@zfs-auto-snap_frequent-2026-07-21-2245 
```
